# 修复列筛选提交无响应

## 做了什么

实际支出页输入金额20–80后点击放大镜未发出请求。前轮菜单关闭修复未覆盖提交；捕获点击先隐藏菜单，React Aria表头还会阻止默认点击，且列筛选form未接入native Grid GET提交。

## 改了哪些

runtime显式触发列筛选表单的校验与submit，将其接入原生PJAX；通过校验后关闭菜单。按钮、图标和Enter共享提交入口，保留输入区和Esc行为。列筛选action已有查询参数保留，本次字段替换旧值且支持同名多值。重置链接也显式走PJAX，避免表头press取消默认跳转；不修改业务金额筛选规则。发布JS及manifest已重建。

## 怎么验证

新增6个回归用例，覆盖按钮、图标、submit、Enter、无效输入与重置；验证保留其它查询条件并替换本次旧值。最初4个提交/校验用例旧实现均失败；最终runtime/navigation/compat-overlays三文件87项测试、typecheck、build、artifact、diff-check通过。测试环境既有jsdom导航提示不影响结果。

Chrome官方扩展实际支出页使用本地编译JS临时预览：20–80提交发出GET Fetch，列表357条变127条，当前页20项金额绝对值均在20–80；Enter提交20–50变99条，375px图标提交20–80变127条。最终脚本CBt0P7HT重新验证20–80为127条，重置后回无过滤URL、357条且输入清空，warn/error为空。仅发送只读GET；视口、拦截、缓存覆盖、验证标签和临时静态服务器已清理。未部署消费应用磁盘资源。
