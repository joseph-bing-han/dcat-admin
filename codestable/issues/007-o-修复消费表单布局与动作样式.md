# 修复消费表单布局与动作样式

对照维护者提供的旧版截图，修复 PayTaxNZ `/admin/expenses/create` 升级后的公共表单回归：尊重 `formWidth(8)`、字段列宽与显式 80px/120px 输入宽度，恢复桌面标签右对齐、必填标记、字段间距、上传按钮和三种保存动作的颜色及顺序。保留现代控件和响应式布局，不引入旧 Bootstrap 运行时。

已确认 `readFormModel`/`FormView` 抽取 card 后丢弃外层 row/column；新 Input 的容器始终 w-full，抵税率宽度没有传到容器；日期/价格等兼容字段缺少 asterisk 样式；`bg-blue-1` 无颜色映射，`.btn-info` 被强制覆盖为 primary-hover，上传按钮被渲染为白色。

实现范围：表单模型与渲染器保存安全的外层布局、输入控件适配显式宽度、公共 form/按钮/uploader CSS；补充有意义的表单回归测试、重建发布资源。现有提示框及 Grid 表头改动继续保留。

验证：聚焦 Form/controls 测试、TypeScript、生产构建和 artifact；官方 Chrome 扩展在独立实际创建页预览修复，核对 formWidth、80px 控件、必填标记、四个 footer 按钮与上传按钮颜色，并检查桌面和375px布局。不提交财务表单、不上传文件或操作关键数据。

Task 完成后回写已验证结果和当前 View spec 的明确兼容事实；常规 issue 保持 open，等待维护者关闭授权。无独立 Talk/Note/Tool 需求，根因和验证记录保留在本事项。当前无可调用子代理，不将自检表述为独立审查。

## 实现与验证结果

2026-10-04：实现已完成，Issue 保持 open，等待维护者验收与关闭。执行正本见 [归档 Task](../tasks/archived/2026-10-04-003-restore-consumer-form-layout.md)。

- `readFormModel` / `FormView` 保存表单 card 的外层 row/column 以及安全的 card、body、fields-group 属性，恢复 `formWidth(8)` 和原有列宽、间距。
- Input 适配器将显式宽度及 flex 应用于上游容器，内部输入使用100%宽度，避免百分比宽度被重复缩放；保持 required、readonly、文本对齐和 FormData 协议。恢复文本 affix 图标与帮助图标。
- 桌面横向表单标签右对齐，原生与兼容字段都显示前置必填星号且不重复。上传按钮使用品牌色；新增动作使用旧版 `#007ee5`，查看动作使用旧版 `#4277cf`，色值集中在 Dcat Tailwind主题中。窄屏 footer 按钮换行时保留8px垂直间隙。
- 17项 Form/controls 回归测试、TypeScript、生产构建、artifact、tokens、form-capabilities、bootstrap-absence 和 diff 检查通过。manifest 引用 `dcat-modern-vswbogst.js` / `dcat-modern-BLRRIn3U.css`；新版发布产物及兼容 facade 均已重建。
- Chrome官方extension在独立实际创建页临时替换本次JS/CSS验证：1912px与1024px外层列均为8/12；日期、金额120px，抵税率80px；375px卡片312px、标签上排、按钮正确换行，表单区域无横向溢出。视口切换后上传原节点保持。截图：[桌面](../../artifacts/expense-form-layout/desktop-1912.png)、[手机](../../artifacts/expense-form-layout/mobile-375.png)。截图为本地验证产物。

验证边界：未提交财务表单、上传文件或更改数据库；PayTaxNZ资源未部署，仅在独立标签页临时预览，现已清理。页面预览前已有 `$ is not defined` 和 `darkMode.initSwitcher` 初始化报错；375px全页仍有外壳导航轻微横向溢出（scrollWidth384），均不作为本次表单样式已解决的范围。构建有既有Sass弃用提示；无独立子代理可调用。
