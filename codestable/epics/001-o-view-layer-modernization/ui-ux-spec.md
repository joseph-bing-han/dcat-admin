# View 层现代化 UI/UE 规范

## 规范地位

本文从 `1.0.0` 起作为 modern View 的冻结设计与验收权威。`1.1.0` 根据用户 2026-09-25 的视觉优化要求更新控件和表面样式；稳定布局、品牌色、字段与动作顺序不变。所有实现与视觉证据须引用本版本；公共模式统一维护，不能在业务页面各自补丁。

目标是现代化视觉、可访问性和实现质量，不改变老用户已经形成的页面布局、导航方向、动作位置和任务顺序。Untitled UI 提供组件参考，不取代本项目的兼容契约和设计令牌。

## 设计原则

1. 熟悉优先：稳定区域和主要动作留在原位置，视觉升级不能变成工作流重排。
2. 安静高效：后台界面服务于扫描、比较和重复操作，避免营销式大标题、装饰性卡片和大面积色块。
3. 密度可控：桌面保持现有高效密度，触控环境扩大操作目标但不隐藏关键能力。
4. 状态明确：默认、悬停、焦点、激活、禁用、加载、成功、警告和错误必须可区分，不能只依赖颜色。
5. 一致可测：所有尺寸来自令牌；动态内容不能推动固定工具栏、表格列和图标按钮跳动。
6. 内容兼容：新版 native 与 compat 内容使用一致的视觉层次；compat island 承载原 Controller 输出，不引入旧版整页 renderer。

## 基础令牌

### 字体

禁止从外部网络请求字体。应用使用以下字体栈：

```css
font-family: Inter, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", Arial, sans-serif;
```

Inter 只有在发布包已合法包含或用户系统已安装时使用；否则自然回退。代码、标识符和等宽数据使用：

```css
font-family: "SFMono-Regular", Consolas, "Liberation Mono", Menlo, monospace;
```

- 全局字距固定为 `0`，禁止负字距。
- 不按视口宽度缩放字号。
- 正文常规字重 `400`，强调和控件 `500`，标题 `600`；禁止用极细或 `700+` 字重制造层级。
- 数字列按需求启用等宽数字 `font-variant-numeric: tabular-nums`。

### 字号与行高

| 令牌 | 字号/行高 | 用途 |
|---|---:|---|
| `text-xs` | 12/16px | 辅助元数据、紧凑标签；不得承载主要说明 |
| `text-sm` | 13/18px | 表格次要信息、紧凑控件 |
| `text-md` | 14/20px | 默认正文、表单、按钮和表格 |
| `text-lg` | 16/24px | 面板标题、Modal 标题 |
| `text-xl` | 18/26px | 页面描述较短的区块标题 |
| `display-sm` | 20/28px | 默认页面标题 |
| `display-md` | 24/32px | 登录或 full-page 页面标题上限 |

页面内禁止超过 `24px` 的标题；紧凑面板禁止使用 display 字级。文本必须换行或截断并提供完整内容访问方式，不能溢出或遮挡相邻控件。

### 间距

使用 4px 基准：

| 令牌 | 值 | 典型用途 |
|---|---:|---|
| `space-0` | 0 | 明确贴合 |
| `space-1` | 4px | 图标内部间隙、紧凑元素 |
| `space-2` | 8px | 同组控件、单元格垂直留白 |
| `space-3` | 12px | 控件内边距、小组间距 |
| `space-4` | 16px | 默认内容间距、移动端页边距 |
| `space-5` | 20px | 表单组间距 |
| `space-6` | 24px | 桌面页面边距、主要区块间距 |
| `space-8` | 32px | 独立页面段落上限 |
| `space-10` | 40px | 登录等稀疏页面专用 |
| `space-12` | 48px | full-page 大区块上限 |

不得引入非 4px 倍数的布局间距；1px 仅用于边框，2px 仅用于焦点轮廓或细微位移。

### 色彩

颜色必须以语义令牌使用，不允许组件内写任意十六进制值。品牌色继承现有识别：

| 语义令牌 | 默认值 | 用途 |
|---|---|---|
| `brand-600` | `#586CB1` | 主要按钮、选中、链接重点 |
| `brand-700` | `#485A98` | 主要按钮悬停 |
| `brand-800` | `#3B4B80` | 主要按钮按下 |
| `brand-100` | `#E9ECF6` | 品牌浅背景、选中行 |
| `brand-50` | `#F5F6FB` | 极浅品牌状态背景 |
| `neutral-950` | `#111827` | 主要文字 |
| `neutral-700` | `#374151` | 次要文字、控件文字 |
| `neutral-600` | `#4B5563` | 辅助文字最低深度 |
| `neutral-500` | `#6B7280` | placeholder、辅助文字 |
| `neutral-400` | `#9CA3AF` | 禁用或纯装饰图标，不承载信息 |
| `neutral-300` | `#D1D5DB` | 强边框 |
| `neutral-200` | `#E5E7EB` | 默认边框、分隔线 |
| `neutral-100` | `#F3F4F6` | hover、禁用背景 |
| `neutral-50` | `#F9FAFB` | 页面次级背景 |
| `white` | `#FFFFFF` | 主内容和浮层背景 |
| `success-700` | `#027A48` | 成功文字/图标 |
| `success-50` | `#ECFDF3` | 成功背景 |
| `warning-700` | `#B54708` | 警告文字/图标 |
| `warning-50` | `#FFFAEB` | 警告背景 |
| `danger-700` | `#B42318` | 错误文字/危险动作 |
| `danger-50` | `#FEF3F2` | 错误背景 |
| `info-700` | `#175CD3` | 信息文字/图标 |
| `info-50` | `#EFF8FF` | 信息背景 |

- 正文和交互元素满足 WCAG 2.2 AA 对比度；普通文字至少 4.5:1，大文字至少 3:1，非文本边界/状态至少 3:1。
- 品牌色只用于交互和关键识别，不作为大面积页面背景。
- 禁止渐变、装饰性光斑、纯气氛背景和以紫蓝色铺满界面。
- 深色侧栏是现有布局配置，可使用独立语义令牌，但必须满足同样的状态与对比度规则。

### 边框、圆角与阴影

| 令牌 | 值 | 用途 |
|---|---:|---|
| `radius-none` | 0 | 表格连续边缘 |
| `radius-sm` | 4px | 紧凑标签、内部元素 |
| `radius-md` | 6px | 下拉、Popover、Toast |
| `radius-lg` | 8px | Modal、Drawer |
| `radius-control` | 8px | 输入、按钮、导航项、Select2 |
| `radius-panel` | 12px | 独立表单、表格和内容表面 |
| `border-default` | 1px | 所有普通边界 |

- 浮层圆角不超过 8px，独立内容表面不超过 12px；胶囊形只用于状态徽标、开关或头像，不用于普通文字按钮。
- 页面区块使用分隔线、背景或留白组织，不把每个区块做成浮动卡片。
- 禁止卡片嵌套卡片。重复独立条目、Modal 和真正需要框定的工具才可使用卡片。
- 输入与按钮允许 `shadow-control: 0 1px 2px rgba(17,24,39,.05)`；静态表面仍以白底、细边框与留白区分，不用大阴影。Popover/菜单使用 `shadow-overlay: 0 4px 12px rgba(17,24,39,.12)`；Modal 使用 `shadow-modal: 0 12px 32px rgba(17,24,39,.18)`。

### 图标

- 优先使用项目确认版本的 Lucide React 图标；不得手绘替代已有通用图标。
- 常规图标 16px，导航/独立动作 20px，空态插图式图标上限 24px。
- 纯图标按钮必须有可访问名称和 hover/focus tooltip；删除、关闭、撤销、下载等熟悉动作优先图标。
- 图标不单独表达错误或成功，必须配合文字或可访问状态。

## 尺寸与密度

| 元素 | 桌面 | 触控/移动 |
|---|---:|---:|
| 默认控件高度 | 40px (`control-height`) | 44px (`control-height-touch`) |
| 紧凑控件高度 | 32px (`control-height-compact`) | 44px |
| 大控件高度 | 40px | 48px |
| 图标按钮可见框 | 34x34px | 44x44px |
| 表格行最小高度 | 40px | 48px |
| 顶部导航高度 | 保持基线测量值 | 保持区域关系，触控目标 44px |
| 展开侧栏宽度 | 260px | overlay/drawer，不改菜单顺序 |
| 折叠侧栏宽度 | 5.4rem，按现有根字号约 75.6px | 不适用 |

固定格式组件必须使用稳定高度、网格轨道、`min/max` 或 `aspect-ratio`；loading、hover、错误文字和计数变化不得造成工具栏、按钮或表头跳动。

原生控件和旧字段适配器共享上述视觉尺寸。上传区采用白底、细虚线边界和品牌 hover/focus 状态；保留原上传图标、按钮、拖拽与错误反馈。Select2 的关闭、展开、选择与禁用状态使用同组令牌，不能退回旧主题。表单标签列宽和字段顺序、导航宽度、Grid 列顺序与横向滚动保持既有契约。

兼容 Widget Form、自定义 Blade 和原生 Form 共享控件外观，不能以是否挂载 React 作为样式生效条件。带前缀或后缀的输入组保持连续边框，外侧圆角为 8px、内部相接角为 0；图标保留原节点和点击行为。只读内容保持可读文字色，禁用状态单独区分。旧主题后加载时不得覆盖 modern 导航项的 8px 圆角。

## 页面布局

### 稳定区域

标准垂直导航布局保持以下视觉顺序：

```text
Brand/sidebar | Top navigation
               Page title, description and breadcrumbs
               Alerts and exceptions
               Main content
               Footer
```

- 布局必须先匹配现有 profile：标准垂直导航、水平导航、full-page，以及 PJAX 启用/禁用组合。不存在于某个 profile 的区域不得为了统一结构而新增。
- 标准垂直布局不改变侧栏导航方向、顶部用户动作区域、标题与面包屑关系、主内容起始位置及页脚归属。
- 水平导航保持菜单位于顶部横向区域，不将其转换成左侧栏；full-page 保持无 sidebar、navbar 和 footer 的最小骨架。
- 桌面展开侧栏保持 260px。折叠模式保持既有窄栏概念和菜单顺序。
- 内容页边距按 M0 对各布局 profile 和断点的实测基线冻结；标准桌面当前以既有 `$content-wrapper-padding: 2.5rem` 为起始证据，不能预设改成 24px。平板和移动同样保持各自基线，只有基线缺失的新容器才可使用 4px 间距体系定义新值。
- 内容最大宽度默认不人为限制，Grid 和复杂 Form 应利用可用宽度；登录/设置类窄表单可使用明确 `max-width`。
- 页面标题一行放置时，主要页级动作留在标题区域右侧；窄屏时动作换到标题下方，顺序不变，不覆盖文字。
- 面包屑允许横向滚动或中间省略，当前页始终可见；不得挤压页级动作到不可用。

### 响应式断点

沿用现有断点以降低行为变化：`576px`、`768px`、`992px`、`1200px`。不得新增只为单一页面修补的断点。

必须验收以下视口：

| 视口 | 主要目的 |
|---|---|
| 390x844 | 手机纵向、触控、菜单 drawer |
| 768x1024 | 平板纵向和窄内容 |
| 1024x768 | 小型桌面/平板横向 |
| 1366x768 | 常见生产桌面高度 |
| 1440x900 | 宽桌面和密集数据 |

- 小于 992px 时侧栏可变为覆盖式 drawer，但入口、菜单分组和顺序不变，关闭后焦点返回触发器。
- 表格优先保留列和横向滚动，不擅自将每行改成卡片；只有对应 Grid Issue 明确定义列优先级时才可隐藏非关键列。
- 固定页级动作在移动端不得遮挡表单字段、分页或系统反馈。
- 200% 缩放与最窄视口下不得出现双轴页面滚动；数据容器可单独横向滚动。

## 组件规范

### 按钮与动作

- 层级只有 primary、secondary、tertiary、danger 和 icon-only。一个动作组默认最多一个 primary。
- 主按钮背景 `brand-600`；危险确认仅在确有不可逆或高影响语义时使用 `danger-700`。
- 按钮文字使用动词，源代码中的显示文本使用英文并进入翻译体系；不使用含糊的 `OK`。
- loading 保持原宽度并显示进度状态，禁止重复点击；disabled 必须有真实原因且不代替权限说明。
- 动作排序继承 legacy。不能为了“现代”把创建、保存、返回、筛选或批量动作移到新位置。

### 表单控件

- 标签位置继承现有字段配置和表单布局：默认 `form-horizontal` 在桌面保持标签左、字段右及既有 label/field 列宽；明确使用非横向模式的字段才将标签置于控件上方。复选框、单选和开关保持现有标签关系。必填标识可见且对屏幕阅读器有语义。
- 横向表单保持基线列间距和字段组节奏；堆叠表单的标签到控件为 8px。控件到帮助文本 4px，字段组默认间距 20px；这些值不能改变现有字段顺序或列宽配置。
- placeholder 只作示例，不能替代标签。帮助文本先于错误文本；错误出现时不删除仍有用的帮助信息。
- focus 使用 2px 可见轮廓并与错误边界共存；不得只改变边框颜色。
- 服务端错误在字段附近展示，提交失败后焦点移到错误摘要或第一个错误字段，并保留用户输入。
- 日期、选择、上传等复杂字段必须支持键盘、屏幕阅读器和触控，且浮层不被容器裁剪。

### Grid 与表格

- 表头与数据左对齐；数值可右对齐；选择列、状态列和动作列使用稳定宽度。
- 默认单元格水平内边距 12px、垂直内边距 8px；表头高度不得因排序状态变化。
- 行 hover 只作辅助，选中行必须有复选状态和背景；焦点行有独立轮廓。
- 行动作保持既有顺序。动作过多时允许保留高频动作并将其余放入菜单，但必须由对应兼容矩阵批准。
- 空态位于表格容器中，说明结果为空并保留适用的筛选重置/创建动作；不得用大幅插图占据页面。
- 加载使用稳定骨架或进度区域，不清空列头和筛选上下文。

### Tabs、菜单与导航

- Tab 表示同一任务内的并列视图，使用正确 ARIA 模式和方向键；不得把页面导航伪装为 Tab。
- 菜单保留分组、图标和顺序；当前项同时具有视觉和语义选中状态。
- 折叠侧栏的图标项必须提供 tooltip；有子菜单时键盘和屏幕阅读器可以展开。
- 数据库菜单与 `Menu::add()` 添加的菜单共享展开行为。二级和三级分组通过点击或键盘切换，`aria-expanded` 与子菜单可见性同步；展开不改变当前 URL，选择叶子菜单才导航。

### Dashboard Metrics 与下拉留白

2026-09-26 用户反馈的修复目标：Metrics 内容沿用 `space-4`（16px）内边距，标题、数值和说明与面板边缘有一致留白；显式设置为零内边距的内容仍尊重其设置。

```text
Metrics panel
|  Title                     [Range v] |
|  Value                     +--------+
|  Description               |  Item  |
|                            |  Item  |
                             +--------+
```

图示为目标展开态：下拉面板以触发器的对齐边锚定，宽度随内容且受视口边界限制，不能拉伸至视口右侧。面板内部使用 `space-2`（8px）留白、条目横向使用 `space-3`（12px）留白；菜单浮于内容上方，不推动卡片或触发器。窄视口、滚动和关闭后的焦点恢复均需实测。

### Modal、Drawer、Popover 与 Tooltip

- Modal 用于需要确认或短任务；长表单和完整详情使用页面或 Drawer。不得在 Modal 内再打开 Modal。
- 打开后焦点进入首个合理元素，Tab 被限制在浮层内，Esc 按语义关闭，关闭后焦点返回触发器。
- 破坏性流程不得仅靠点击遮罩关闭；存在未保存输入时必须明确处理。
- Popover/菜单进行视口碰撞检测，移动端必要时变为 Drawer；不得遮挡触发器和主要反馈。
- Tooltip 只补充短说明，不承载完成任务所需的信息；触控和键盘必须有等价访问路径。

### 反馈状态

- Alert 用于页面内持久反馈，Toast 用于无需持续参考的操作结果，字段错误贴近字段。
- Toast 桌面位于右上安全区，移动端位于顶部并避开导航；同时最多显示 3 条，超出排队。
- 成功状态默认自动关闭但必须可被辅助技术读出；错误状态保持足够时间或等待用户关闭。
- 所有异步区域定义 idle、loading、success、empty、error、disabled 和 permission-denied 状态。
- 错误文案说明发生了什么和可执行动作，不泄漏堆栈、路径或敏感数据。

## 交互与动效

- 普通颜色/阴影过渡 120ms，展开/浮层 160-200ms；只使用标准 ease-out/ease-in，不使用弹簧、弹跳和视差。
- 动效只能解释状态和空间关系，不能装饰等待过程。
- `prefers-reduced-motion: reduce` 时移除位移和缩放，仅保留必要的即时状态变化。
- 禁止通过 hover 才显示完成核心任务所需的唯一动作；键盘 focus 和触控必须等价。
- 提交、导航和 PJAX 切换期间必须保持可理解的忙碌状态，不能让用户误以为动作未触发。

## 无障碍门禁

- 目标为 WCAG 2.2 AA。所有功能可仅用键盘完成，焦点顺序与视觉顺序一致。
- 每页有唯一主标题和语义区域；页面语言、表单标签、表头关联、状态 live region 和错误关联完整。
- `:focus-visible` 清晰可见且不被 overflow 裁剪；sticky 区域不得遮挡被聚焦元素。
- 颜色不是唯一信息载体；状态配合文字、形状或图标。
- 支持 200% 缩放、系统高对比模式和 reduced motion；主要任务不依赖精确拖拽。
- 自动扫描不能替代人工键盘、焦点返回、屏幕阅读顺序和缩放验收。

## 文案与本地化

- 新增源代码中的 label、message、日志和可见文本必须使用英文，并通过现有翻译机制提供本地化；代码注释使用中文。
- 复用现有业务术语和动作名称，不擅自改写老用户熟悉的菜单、按钮与字段名。
- 避免用界面可见文字解释组件如何使用、键盘快捷键或设计特征；界面本身应可理解。
- 日期、数字、时区、复数和文本方向遵循当前应用 locale，不在 React 组件内硬编码格式。

## AI 与实现门禁

AI 生成设计或代码时必须遵守：

1. 只能使用本文令牌；发现缺失令牌时停止局部发挥，先提交规范变更。
2. 不改变稳定布局、动作顺序、字段名称、查询参数或请求语义。
3. 不新增渐变、装饰性背景、超大标题、营销式 hero、嵌套卡片或超过 8px 圆角。
4. 不在单个页面复制基础组件或写私有颜色/间距；复用受控组件。
5. 每个组件实现全部状态、键盘路径、焦点规则、响应式约束和新版 compat 内容路径。
6. 引入 Untitled UI 代码前记录来源、版本和许可证；不得假定 PRO 组件可用。
7. 截图更新必须对应规范条款和人工确认，不能将意外差异批量设为新基线。
8. 完成前扫描 CSS 颜色、间距、圆角、z-index 和字体声明，拒绝未令牌化值。

## 视觉验收清单

- 五个规定视口均无元素重叠、文字截断失联、不可达操作和页面双轴滚动。
- 稳定区域、主要动作、表格列顺序、表单字段顺序与 legacy 基线一致。
- 默认、hover、focus、active、disabled、loading、success、warning、error 和 permission 状态均有证据。
- 浮层在视口边缘、滚动容器、sticky 导航和 PJAX 切换中正确定位并清理。
- 亮色、现有深色/主色侧栏配置及高对比模式达到对比度门槛。
- 390px 触控目标不小于 44px；桌面普通控件 40px、紧凑控件 32px，尺寸不因文字或 loading 改变。
- 字体缺失和超长翻译时布局仍稳定；没有外部字体请求。

## 规范变更流程

令牌、稳定布局或跨组件交互规则的修改属于共享契约变化：必须建立独立 Issue，说明动机、受影响组件、迁移方式、视觉证据和回退，并扩大相关页面族验证。单个业务页面不得覆盖本文形成隐式例外。
